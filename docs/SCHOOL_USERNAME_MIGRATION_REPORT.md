## แผนดำเนินการ

1. ยืนยันรหัสที่จับคู่ได้กับผู้ดูแลข้อมูลเขตพื้นที่
2. ตรวจรายการที่ไม่พบใน Big Data แยกตามสังกัด: สช., ตชด., การศึกษาพิเศษ หรือชื่อโรงเรียนที่เปลี่ยน
3. เพิ่มคอลัมน์ `school_code` แบบ unique โดยยังไม่แก้ `users.email`
4. Import และตรวจรหัสซ้ำ/รหัสชนบัญชีเดิม
5. สำรองตาราง users และสร้างตาราง mapping username เดิม → ใหม่
6. ทดลอง login ด้วยบัญชีตัวอย่างทุกเครือข่าย
7. เปลี่ยน username แบบ transaction และบันทึก audit log
8. เปิดช่วงผ่อนผันให้ username เดิม login ได้ชั่วคราว แล้วจึงยกเลิกเมื่อโรงเรียนรับทราบครบ

## ประเด็นสำคัญ

- บัญชีโรงเรียนอนุบาลชุมพรในระบบใช้ `86010020` แต่ Big Data ระบุ `86010008`
- รหัส `86010020` ใน Big Data เป็นของโรงเรียนวัดทุ่งคา
- จึงไม่ควรเปลี่ยน username ทั้งหมดด้วยสคริปต์ทันทีจนกว่าจะตรวจและอนุมัติ mapping
